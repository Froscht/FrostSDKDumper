## 4. Crypto Pipelines (Quick Reference)

### A. UObject Slot Decrypt (NameIndex / ClassPrivate / Outer)

```
Pipeline: ROL32(15) → PSHUFB({0x05,0x02,0x07,0x06,0x01,0x00,0x04,0x03})
          → ROL16(4) → ROL64(32) → lo64
```

**Slot index:** `((-109*(temp1>>8)+61) ^ ((v6eq>>16)&0xFF)) & 3 ^ 2`
with `temp1` from FNV chain seeded by `obj_addr+16`.

| Use | Slot formula |
|---|---|
| NameIndex | `idx` |
| ClassPrivate | `idx ^ 2` |
| Outer | `idx ^ 3` |

### B. FField Name Decrypt (`+0x90`, 8 bytes only — 2nd 8 = ROR64(first,16) self-check)

```
PSHUFLW(0x39) → ROL64(33) → AND(0x84)/ANDNOT(0x7B) blend
→ PSHUFB({7,2,3,6,5,0,1,4}) → PXOR(0xB5B5A3D2F313FAB5)
→ ROL64(32) → lo64 = (Number<<32) | pool_index_29bit
```

**Optimisation:** blend (A=~B per byte) collapses to `v XOR 0x7B...`,
then commutes through PSHUFB into single XOR with effective key
`{0x31,0x7E,0x97,0x77,0x56,0x27,0x31,0x31}`.

### C. CI → FNameEntry Resolver (the big fix)

```
CI = uint29_t (low 29 of FName u64)
  bits 16..28 = chunk_idx
  bits 0..15  = name_offset_word

module_cache_ptr  = *(GNAMES + 0xC8 + 0x10)   // SHARED across ALL chunks!
sub_block_off     = (CI >> 8) & 0x1FFF00
block_base        = module_cache_ptr + sub_block_off

→ FNV hash on (block_base+16) → block_idx
→ Read 2x 16-byte blocks at +32+32*idx
→ PSHUFLW(0x2D) → ROL16(15) → FNV-fold
→ Pointer fixup chain → FNameEntry heap address
```

**Key gotcha:** the `+0xD8` pointer is shared, NOT per-chunk. The
per-chunk heap blob at `+0xD0` is for hashtable lookup, not direct
resolve.

### D. FNamePool Chunk Layout

```
chunk_addr = GNAMES + 0xC8 + chunk_idx * 0x40   // stride 0x40, start +0xC8
chunk_addr + 0x00 : u32 count_lo, u32 max (0x7FF)
chunk_addr + 0x08 : u64 per-chunk heap pool ptr
chunk_addr + 0x10 : u64 SHARED module cache ptr (= 0x14DB4CFC0 always)
chunk_addr + 0x18 : u32 count duplicate
```

### E. FName String Decrypt (in `FNameEntry_Compare`)

```
header u16: bit15 = isWide, bits 0..13 = length
ANSI: key = (uint16)(length - 25184); buf[i] ^= keyTable[(key+i) & 0x3F] >> 3
Wide: key = length + 40352;            word[i] ^= keyTable[(key+i) & 0x3F]
keyTable = 64×u16 at RVA 0xDA8D854 (sequential, no offset)
```

## 6. Next-Patch Playbook (READ THIS FIRST!)

When the game patches and the dumper breaks:

### Step 1 — Boot the game and find process

```bash
sudo ./build_and_run.sh $(pgrep GameThread)
```

If it crashes early ("Cannot decrypt GNAMES" / "GObject count = 0"):
- Read RVA `0xDB48E80` and `0xDE04650` — if all zeros, those globals MOVED.
- Find new RVA via string anchors (Section 3) — xref `UObjectArray.cpp`,
  follow large data references.

### Step 2 — Quick check: what crypto changed?

Try the dumper. Look at output:
- **Few/no names resolve (~5K)** → `ResolveNamePtrFull` block constants changed,
  OR the `module_cache_ptr` formula changed. Check `chunk_addr + 0x10` for the
  shared cache pointer.
- **Many `Prop_CI<n>` fallbacks** → FField name decrypt at `+0x90` changed.
  Open IDA at `FField_GetFName_CompareCI_NEW` (RVA `0x428C57`), check if
  the constants `BlendKeyA/B/XorKey/PSHUFB_Mask` shifted.
- **Garbage enum values** → `UEnum::Names` offset moved (was `0xB0`). Scan
  offsets `0xA0..0xC0` of any UEnum looking for `(heap_ptr, count, count)`
  pattern where `count == max`.
- **No functions detected** → `funcMetaAddrs` empty. Function metaclasses
  (Class objects named "Function"/"DelegateFunction"/"SparseDelegateFunction")
  may have moved or their decrypt failed.

### Step 3 — Use IDA `qoc9` as the reference

The renamed symbols + comments in `qoc9` show the EXACT pipeline the game
uses. For each pipeline change:

1. Open the relevant function (e.g. `FField_GetFName_CompareCI_NEW`).
2. Compare its decompile to the new patch's equivalent.
3. Use **string anchors** (UObjectArray.cpp etc.) to find the sister
   function in the new binary.
4. Update constants in `arc_decrypt.h` / `fname_decrypt.h` /
   `sdk_generator.h`.

### Step 4 — Find changed offsets fast

Run `python3` snippets like the one in `feedback_property_chains.md`:
- For UObject offsets: dump 256 B at known objects, look for ROR16 self-check
  patterns at varying offsets.
- For TArray fields (Names, etc.): scan u64 (heap ptr) followed by u32 == u32
  pattern.

### Step 5 — Functions checklist (highest signal)

If everything is broken, validate each pipeline IN THIS ORDER:
1. **GObjectArray chunk pointer decrypt** (`gobjects.h::DecryptChunkPtrDirect`).
   Without this, you get zero objects.
2. **UObject NameIndex slot decrypt** (`fname_decrypt.h::DecryptFNameRaw`).
   Without this, no class names.
3. **FName CI → entry resolver** (`fname_decrypt.h::ResolveNamePtrFull`).
   Without this, all names are empty.
4. **FField NamePrivate decrypt** (`DecryptFFieldNameCI`).
   Without this, all properties are `Prop_CI<n>`.
5. **UEnum::Names offset** (`arc_decrypt.h`).
   Without this, enums have garbage values.
6. **UStruct::ChildProperties offset** (`0x100`).
   Without this, no properties at all.
7. **FProperty::Offset_Internal** (`0x0EC`, XOR `0x2AB03FD6`).
   Without this, all property offsets are wrong.

### Step 6 — Live debugging tools

- **`mcp__memory-reader__read_memory`** — read live process memory by PID.
- **`mcp__ida-multi-mcp__decompile`** — get IDA decompile of any RVA.
- **`mcp__ida-multi-mcp__find_regex`** — find string anchors.
- **`mcp__ida-multi-mcp__xrefs_to`** — find functions referencing a global.

### Step 7 — Common debug snippets

```python
# Find Names array offset for a given UEnum
import struct
b = bytes.fromhex(HEX_DUMP_OF_UENUM)
for i in range(0, len(b)-15, 8):
    ptr = int.from_bytes(b[i:i+8], 'little')
    cnt = int.from_bytes(b[i+8:i+12], 'little')
    mx  = int.from_bytes(b[i+12:i+16], 'little')
    if 0x10000 < ptr < 0x800000000000 and 0 < cnt <= 1000 and cnt == mx:
        print(f"+0x{i:02X}: Names? ptr=0x{ptr:X}, cnt={cnt}")
```

## 7. What Took FOREVER Last Time (Avoid These!)

Lessons from this patch's debugging session:

1. **`UEnum::Names` is at `+0xB0`, not `+0xA8`.**
   I burned an hour finding only 70 enums before checking the offset moved.
   **Lesson:** when struct counts are way off, scan offsets first.

2. **`FNAME_CHUNK_BLOCK_PTR_OFF = 0xD8` is the SHARED cache, not per-chunk.**
   Two hours debugging "block resolver returns zero" before realising the
   missing piece was `+ ((CI >> 8) & 0x1FFF00)`. The game's
   `FNamePool_FindOrAddEntry` (sub_2408F0) shows it inline — read THAT
   function FIRST when name resolution is broken.

3. **UFunction parameters are FFields at `+0x100`, not UProperty at `+0xE0`.**
   Old patch used UProperty chain in `UStruct::Children`. New patch uses
   `ChildProperties` like everything else. Always scan `0xE0..0x110` for
   FField chains.

4. **K2 functions can have sparse UObject slots.** Some UFunctions have only
   ONE of their 4 NameIndex slots populated (e.g. `K2_AddActorWorldOffset` at
   `0x8518F630` only has slot 3). `GetClassPrivate` returns garbage for
   these. Pass 4 of the UFunction discovery handles this case via vtable
   match.

5. **Wine module base = `0x140000000` via memfd**, NOT `0x100200000` (that's
   just the PE header stub). Find via `pgrep GameThread`, then look at
   `/proc/$PID/maps` for the `0x140000000-` range.

6. **The "no xrefs" trap.** Many MSVC-emitted helpers (e.g.
   `FField_GetFName_CompareCI_NEW`) have ZERO callers in IDA because they
   got inlined everywhere. They're still real algorithms — just not directly
   reachable. Use string anchors + decomp instead of xref chains.

7. **CIs in 67K..10M range are valid**, not bogus. Don't validate CI
   ranges with `< 500000` like I did in `arc_decrypt.h::Offsets::UEnum`
   heuristic — that masked 99% of valid enums. CI is a 29-bit pool index.
